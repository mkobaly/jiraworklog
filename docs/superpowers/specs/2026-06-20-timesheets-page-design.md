# Timesheets Page — Design

**Date:** 2026-06-20
**Status:** Approved (design); pending implementation plan

## Goal

Add a new **Timesheets** report tab, similar to the Weekly Hours page, for
month-over-month timesheet reporting. The page lets a user pick a From/To
year-month range and a Roles filter, then shows, per author, hours grouped by
**raw project charge code** with one column per month — making it easy to spot
when an employee is logging more or fewer hours to a given project charge over
time. Month-over-month increases/decreases beyond ±10% are highlighted with
subtle green/red cell tints.

## Use cases

- "Just run the previous month": select From = `2026-05`, To = `2026-05`.
- "Compare a range": From = `2026-01`, To = `2026-05` → each year-month is its
  own column, so trends per project charge are easy to read across the row.

## Constraints / decisions

- **Charge grouping:** rows are grouped by the **raw `issue.projectcharge`
  string** (most granular — one row per distinct charge an author logged to).
- **Trend baseline:** each month cell is compared to the **immediately
  preceding month column** for the same author + project charge.
- **Totals layout:** each project-charge row ends with a **Total** column (sum
  across months). After an author's charge rows, an emphasized **author-subtotal
  row** sums each month column plus a grand total.
- **Default range on first load:** From = To = the **previous completed month**
  (e.g. today is June 2026 → `2026-05`).
- **Current month excluded:** the current (incomplete) month must not be
  selectable.

## Architecture

Mirrors the existing Weekly Hours and Project Charge Hours pages.

### 1. Routing & navigation

- New route `GET /reports/timesheets` → handler `GetTimesheets`, registered in
  `cmd/jiraworklog/main.go` in the `reports` group (auth middleware), alongside
  `/reports/weekly-hours`.
- New **Timesheets** nav link in `templates/layouts/base.templ` `Navigation()`
  component, added to both the desktop (~line 133) and mobile (~line 153) link
  lists, next to Weekly Hours.

### 2. Filters & date handling

- Two `<input type="month">` pickers (From / To), as on the Project Charge Hours
  page (`templates/pages/projectchargehours.templ`), values in `YYYY-MM` format.
- Each picker gets a `max` attribute set to the **last completed month** so the
  current month cannot be selected in the UI.
- **Server-side clamp:** the handler clamps any From/To value that is the current
  month or later down to the previous completed month, as a safety net beyond the
  `max` attribute. If From > To after parsing, set From = To.
- **Default:** when From/To are absent, both default to the previous completed
  month.
- **Roles** filter: identical to Weekly Hours — multi-select checkboxes populated
  from `repo.AllRoles()`, defaulting to all roles when none are selected
  (`c.QueryParams()["roles"]`).

### 3. Data layer

New repository method on the `Repo` interface and `Postgres` implementation:

```go
func (s *Postgres) TimesheetHours(roles []string, from, to time.Time) ([]types.TimesheetHours, error)
```

SQL mirrors `DailyHoursByRole` but groups by author, raw project charge, and
year-month:

```sql
SELECT
    p.role,
    w.author,
    i.projectcharge,
    to_char((w.date AT TIME ZONE 'America/New_York'), 'YYYY-MM') AS yearmonth,
    SUM(w.timespenthours) AS hours
FROM worklog w
JOIN issue i ON w.issueid = i.id
JOIN people p ON w.author = p.name
WHERE w.date >= ($2 AT TIME ZONE 'UTC')
AND w.date < ($3 AT TIME ZONE 'UTC')
AND p.role = ANY($1)
GROUP BY p.role, w.author, i.projectcharge, yearmonth
ORDER BY w.author, i.projectcharge, yearmonth;
```

- `$1` = selected roles, `$2` = first day of From month (UTC), `$3` = first day
  of the month **after** To (exclusive upper bound). Note `< $3` (exclusive),
  unlike `DailyHoursByRole`'s inclusive `<= $3`, to cleanly span whole months.

New domain type in `types/`:

```go
type TimesheetHours struct {
    Role          string  `db:"role"`
    Author        string  `db:"author"`
    ProjectCharge string  `db:"projectcharge"`
    YearMonth     string  `db:"yearmonth"`
    Hours         float64 `db:"hours"`
}
```

### 4. Pivot / view model

The handler pivots flat `[]TimesheetHours` into an author-centric structure and
generates the ordered list of month columns spanning From→To inclusive:

```go
type TimesheetChargeRow struct {
    ProjectCharge string
    MonthHours    map[string]float64 // "YYYY-MM" -> hours
    Total         float64
}

type TimesheetAuthor struct {
    Author      string
    Role        string
    Charges     []TimesheetChargeRow
    MonthTotals map[string]float64 // "YYYY-MM" -> sum across charges
    GrandTotal  float64
}
```

- `months []string` — ordered `YYYY-MM` columns from From to To inclusive
  (generated by stepping month-by-month).
- Authors ordered alphabetically; charges ordered alphabetically within author.

### 5. Table rendering

Columns: `Author | Project Charge | <month₁> … <monthₙ> | Total`

- One row per project charge under each author; the Author cell shows once per
  author (rowspan or blank on subsequent rows).
- Each charge row ends with its across-months **Total**.
- After each author's charge rows, an emphasized **author-subtotal row** sums
  each month column and shows the grand total.
- Cells with no hours for a month render as a blank/dash and count as neutral.
- Wide table uses horizontal scroll, consistent with existing report pages.

### 6. Trend coloring

Applies **only** to per-charge month cells (not the Total column, not the
author-subtotal row, not the first month column):

- Compare each month cell to the **previous month column** for the same
  author + charge.
- `pct = (cur - prev) / prev`.
- If `prev == 0` → neutral (no baseline). First month column → always neutral.
- `pct > +0.10` → subtle green tint; `pct < -0.10` → subtle red tint; else
  neutral.
- "Subtle" = light translucent tints (e.g. `bg-green-50` / `bg-red-50` or
  low-alpha rgba) so the number stays readable. A small legend explains the
  colors.

## Testing

Following the repo's integration-test pattern (`go test ./test/...` against the
DB configured in `bin/config.yaml`):

- Test `TimesheetHours` returns rows grouped by author/charge/month with correct
  summed hours over a known date range.
- Verify range bounds: From month is included; the month after To is excluded
  (i.e. To's month is fully included, the following month is not).

## Out of scope (YAGNI)

- No CSV/Excel export (can be added later if needed).
- No per-cell drill-down to underlying worklogs.
- No configurable trend threshold (fixed at ±10%).
- No mobile card view beyond what horizontal scroll provides (the existing
  report pages set the precedent; can revisit if needed).
